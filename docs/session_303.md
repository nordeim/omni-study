## 五项修复（TDD：先 RED 后 GREEN）

RED 阶段先行：4 个单元引脚与 10 个 e2e 引脚精确按发现预测失败。随后：

1. **缺失的文件夹删除路由（高）** — `DELETE /api/files/folders/[id]` 自 S13 文件功能起就从未存在：客户端在调用、UI 在渲染垃圾桶按钮、每次点击都 404。文件夹可以创建却永远无法通过 UI 删除。没有任何规范覆盖文件夹删除 — 这就是 299 次绿色会话漏掉它的原因。修复采用 `files/[id]` 的所有权模式，级联由模式的 FolderTree 与 FileItem.folder 关系处理。
2. **AI 失忆（中）** — LLM 上下文查询读取的是最旧的 20 条消息（`asc + take 20`）：一旦超过 20 条存储消息，助手提示词永远不包含最近的对轮。修复为 desc + take 20 + reverse（按时间顺序注入提示词）；引脚沿用 theme-cache 先例（路由为服务端专属，无法导入 vitest — 源码不变式引脚即是同步契约）。
3. **抽屉焦点机制（中，所有者优先面）** — 抽屉已有 role/aria-modal/Escape 关闭，但缺少打开时的焦点移入、Tab 循环陷阱、焦点归还、主体滚动锁定，汉堡按钮缺 aria-expanded。修复落在现有纯实现上（不引入 Radix Dialog，DOM 结构与全部奇偶校验引脚不变），全部为参考站零 aria 抽屉之上的严格超集。
4. **损坏哈希防护（低）** — 空或乱码十六进制的哈希段解码为零长度缓冲区，`timingSafeEqual(∅, ∅)` 为真：损坏的行接受任意密码。修复为 64 字节预期长度防护。
5. **P2003 映射（低）** — 客户端提供的无效外键 ID 呈现为 500；现为 400 与可操作的消息。
