**The five fixes, TDD.** The RED phase ran first: four unit pins and ten e2e pins failing exactly as the findings predicted (two e2e passing vacuously through the missing route's own 404 — the classification noted before the fix). Then:

1. **The missing folder-DELETE route** — `DELETE /api/files/folders/[id]` simply never existed. The client called it; the Files view rendered the trash button; every click 404'd. Folders could be created but never deleted through the UI — since the S13 files build. No spec ever covered folder deletion, which is how 299 green sessions missed it. The fix is the `files/[id]` pattern verbatim: requireUser, the ownership findFirst, the cascade handled by the schema's FolderTree and FileItem.folder relations.
2. **The AI amnesia** — the LLM context query read `orderBy: "asc", take: 20`: the OLDEST twenty messages. Past twenty stored messages, the assistant's prompt never contained the recent turns — the flagship AI feature silently degraded with use. The fix: desc, take twenty, reverse for chronological injection. The pin follows the theme-cache precedent — the route is server-only (Prisma + the dynamic SDK import) and cannot be imported into vitest, so the source-invariant pin IS the sync contract.
3. **The drawer focus mechanics** — the owner's priority surface. The drawer carried role, aria-modal, Escape-close, and the labelled backdrop, but no focus move on open, no Tab trap, no focus restore, no body scroll lock, and the hamburger had no aria-expanded. The web-app-foundation skill lists focus-trap and scroll-lock as the non-negotiable drawer supersets. The fix went onto the existing plain implementation — no Radix Dialog, no DOM restructure — a useEffect that focuses the close button, traps Tab within the panel, locks the body, restores focus to the hamburger, and the aria-expanded/aria-controls pair. Every standing drawer pin held: the drawer-check's six checks green, the parity specs untouched, and the capture-delta proved the mechanics render zero pixels.
4. **The corrupted-hash guard** — an empty or garbage-hex hash segment decoded to a zero-length buffer, scryptSync with keylen 0 returns a zero-length buffer, and `timingSafeEqual(∅, ∅)` is true: a corrupted row authenticated any password. One guard line — the expected hash must be the fixed 64 bytes this app writes.
5. **The P2003 mapping** — a client-supplied FK id pointing at a nonexistent row surfaced as a 500 with a server-error log line. Now a 400 with an actionable message, mapped beside its P2002/P2025 siblings.
